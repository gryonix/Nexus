# gryonixnexusd — the control-plane agent

The agent runs on every server the app manages. It owns the server's state,
does the work and answers the apps through a local Unix socket, which the apps
reach over SSH. It has no public port.

The agent is built on the server itself. The app sends `bootstrap/install-agent.sh`
over SSH, and the script builds the agent from the sources in this folder.

## Layout

```
gryonixnexusd/      the agent (Rust, one static binary): src/ and tests/
bootstrap/          install-agent.sh, the script the app sends over SSH; small helper scripts
systemd/            unit files for the agent and the mDNS alias service
../Proto/           the API contract (gryonixnexusd.proto), the one source of truth
```

Swift and Kotlin clients are generated from the same schema in `Proto/`, and the
Rust types are generated by `gryonixnexusd/build.rs`.

## Rules

- The socket is local, and every call comes from the agent's own user.
- The engine lives in the agent. There is no generic exec call; a client sends a
  catalog id and a verb.
- Functions stay under 80 lines.

## Talking to an agent

`gryonixnexusd bridge` splices stdin and stdout onto the socket; the app runs
`sudo gryonixnexusd bridge` over an SSH exec channel and speaks Connect over it.
`gryonixnexusd pair-code` prints a one-time code (ten minutes) that enrols a
device; it is never reachable over the API. `gryonixnexusd version` prints the
installed version.

## Updates

Installed agents check for a signed release manifest and install newer versions
themselves. The agent's source is also published as its own repository,
[github.com/gryonix/nexus-agent](https://github.com/gryonix/nexus-agent).
