# gryonixNexus — Swift packages

A local Swift package with the logic behind the Apple apps. It does not depend
on UIKit or AppKit, so it is tested in isolation.

## Targets

- **gryonixNexusCore** — recipe-independent core: recipe and generator protocols,
  domain models (`Domain`, `NetworkAddress`, `ServerNode`, `Topology`), artifacts,
  the central security policy (`SecurityPolicy`) and distribution profiles.
- **MailRecipe** — the mail recipe on top of the core: ready-to-run setup scripts
  (Postfix, Dovecot, TLS, DKIM, nftables, WireGuard) and DNS records.
- **ServiceCatalog** — the managed services, their context, hostnames, updates
  and uninstall specs. Shared by generation and the management UI.
- **ServerControl** and **ServerControlSSH** — the management layer and its SSH
  transport.
- **AgentClient** and **AgentClientSSH** — the client for the server agent
  (`Server/gryonixnexusd`).
- **VPNProfile** and **VPNTunnel** — VPN profiles and the tunnel configuration.

## Output principle

Generation produces **ready-to-run shell scripts**, not instructions. There are
at most two scripts per recipe:

- **single host**: `setup-mail-server.sh` runs once on one server with a public
  address. It sets up the firewall, TLS (Let's Encrypt), Postfix, Dovecot and DKIM,
  and ends with a status report and the DKIM DNS record.
- **VPS relay with a home backend**: `setup-vps.sh` (the WireGuard entry point,
  DNAT of the mail ports into the tunnel, and symmetric SNAT and MASQUERADE so
  outgoing mail leaves from the VPS address that matches PTR and SPF) and
  `setup-home-server.sh` (a WireGuard client with a full tunnel plus the whole
  mail stack). Each script is self-contained and runs once on its own machine.

The one artifact outside the scripts is `dns-records.txt` (MX, SPF, DKIM, DMARC).
Those records are set at the DNS provider and cannot be applied by a server script.

Every script uses `set -euo pipefail`, checks for root and for the distribution
(fixed at generation time), installs packages non-interactively, backs up configs
before overwriting them, can be re-run safely, and prints a report at the end.

## Keys

- **WireGuard** (relay scenario only): the app on the user's device generates the
  key pairs (CryptoKit, X25519). Otherwise the two scripts could not be independent
  and run once. Each machine's private key goes **only** into that machine's script,
  and scripts must be moved over a secure channel (scp or SSH).
- **DKIM**: the key is generated by the script on the server and never leaves it.
  The public TXT record is printed in the script's report.

## Module boundaries

- The core knows nothing about mail. A new recipe is a new target on top of
  `gryonixNexusCore`.
- Generation runs entirely in memory: templates are built by Swift code, no
  resource files are read from disk, and nothing is sent anywhere.
